# Проектирование железных дорог (план, профиль, ИП) через AutoCAD MCP

Скилл ведёт задачу ЖД-проектирования от вводных до выдачи DXF + PDF + расчётных таблиц. Расчётная геометрия — детерминированными скриптами (точные формулы), черчение — инструментами autocad-mcp с постусловиями. Язык общения и чертежей — русский; идентификаторы слоёв, скриптов и JSON-ключей — английские.

## Назначение и границы

- План трассы: прямые вставки, круговые кривые (дуги ARC), переходные клотоиды (полилинии по Френелю), пикетаж с уравниванием (домер).
- Продольный профиль: сетка по СПДС, земляной/проектный профили, уклоны в ‰, вертикальные кривые, рабочие отметки.
- Возвышение наружного рельса: h = 12,5·V²/R с проверкой лимитов; стрелочные переводы: угол крестовины, съезды, условные обозначения.
- Комплект: DXF, PDF (фиксированный масштаб), расчётные таблицы JSON, журнал проверок.

Не входит: Civil 3D-коридоры, поперечные профили/земляные работы, объёмы, путевое развитие сложных станций (горловины), прочностные расчёты. Нормативы из памяти не принимать — см. «Нормативный контракт».

## Принципы

- **Безопасность черчения.** Исходник пользователя не изменяется без явного разрешения; новая работа — в новом/копийном документе. Атомарные партии (`entity` → `create_batch`, `atomic: true`); откат — `undo` или удаление только собственных хэндлов с доказательством счётчиков.
- **Идентичность документа.** После каждого `create/open/activate/save/save_as_dxf/plot_pdf/render_preview` — чтение `drawing` → `context` и сверка `doc_id`, пути, revision. Каждая мутация несёт `doc_id` + `expected_revision`. Расхождение — стоп этапа (`E_DOCUMENT_ID_MISMATCH`), никаких «тихих» переключений документов.
- **Постусловия.** Ответ create-операций содержит requested/actual/diff — сверяй до следующей зависимой операции. Необъяснённое расхождение координат/слоя/типа = провал, а не предупреждение: один ограниченный recovery, затем смена бэкенда или `BLOCKED`.
- **Транспорт.** Один FIFO-поток вызовов; параллельные мутации и скриншоты запрещены. Ошибка очереди/лимита — стоп раунда с сохранением доказательств.
- **Один источник истины на число.** Координаты НК/КК/СЦ, пикетаж, возвышение рождаются в скрипте и переносятся в чертёж как есть. Подгонка цифр в чертеже запрещена: расхождение = дефект источника, чинить источник.
- **Раздельные доказательства.** Геометрия (DRC), содержание (расчёт vs чертёж), изображение (preview), печать (plot-scale) — разные проверки с разными выводами; общий флаг «валидировано» запрещён.

## Нормативный контракт

Каждое нормативное число в ссылках скилла либо имеет источник (название документа — без выдуманных пунктов), либо помечено «уточнить». При применении: значение с пометкой «уточнить» разрешено только как временное с явной пометкой в расчётной таблице и в отчёте; нормоконтроль и принятие нормативов — человек. Скрипты печатают источники в JSON (`constants.sources` / `warnings`).

## Входные данные (запросить у пользователя до расчётов)

Обязательный минимум intake; отсутствующее помечать `TBD` и не заполнять фикцией:

1. Назначение и категория линии, допускаемые скорости (пасс./груз.).
2. Геометрия трассы: координаты/пикетаж начала, дирекционные углы вставок, углы поворота ВУ, радиусы R, длины переходных L (или «назначить по нормам — решает проектировщик»).
3. Продольный профиль: земляные отметки/данные уклонозасечки, проектные уклоны и отметки переломов, масштабы (гор./верт.).
4. Возвышение: скорости и радиусы по кривым (для `cant_calc.py`), либо готовые h.
5. Стрелочные: марки, типы рельсов, альбомные размеры Lп/a (если есть), расстояния между осями путей E.
6. Бэкенд: DWG с живым AutoCAD или headless DXF. Формат выдачи (DXF/PDF), масштабы печати, требования к штампу.

## Workflow

1. **Intake и классификация.** Собери входные данные (выше), зафиксируй TBD. Классифицируй: план / профиль / комплект / стрелочные. Без исходных координат — только расчётные таблицы и заготовки.
2. **Расчёт геометрии.** Для каждого угла поворота:
   `uv run python skills/railway-design/scripts/track_geometry.py --angle-deg <θ> --radius <R> --spiral <L> --station-vu <ПК_ВУ_в_метрах> --turn left|right`
   → элементы T/K/Б/Д, Tp/K₀/Kfull/Бp/Д, координаты НК/ВУ/НКК/ККК/КК/СЦ/Ц, пикетаж. Клотоиды для черчения:
   `uv run python skills/railway-design/scripts/clothoid_points.py --radius <R> --length <L> --points 33 --origin-x <X> --origin-y <Y> --direction <угол°> --side left|right`
   → `points` для `entity` → `create_polyline`.
3. **Слои.** Создай документ (`drawing` → `create`/`open`), прочитай `context`. Примени `assets/layer-scheme.json` через `layer` → `create` (параметры name/color/linetype/lineweight), проверь постусловие `layer` → `list` со схемой. Схема слоёв и режимы единиц — [references/layers-and-standards.md](references/layers-and-standards.md).
4. **План трассы.** Вставки — `create_line`; круговые — `create_arc` (центр/углы из координат Ц); клотоиды — `create_polyline` из шага 2 (шаг дискретизации — [references/track-plan.md](references/track-plan.md) §5). Вспомогательные построения — `RW-CONSTR`. Постусловия: `entity.get` стыковых точек (допуск 1e-6 м).
5. **Пикетаж.** Подписи ПК из `chainage` скрипта (`annotation` → `create_text`/`create_leader`, слой `RW-CHAINAGE`); домер учесть при переносе пикетажа за кривую. Контроль: `ПК КК − ПК НК = Kfull`.
6. **Профиль.** Заготовка сетки:
   `uv run python skills/railway-design/scripts/profile_grid.py --length-m <м> --start-pk <ПК> --h-scale 5000 --v-scale 1000 --out profile_grid.dxf`
   Затем чёрный/красный профили полилиниями, тексты отметок, графы уклонов. Геометрия вертикальных кривых и правила — [references/longitudinal-profile.md](references/longitudinal-profile.md). Контроль отметок — пересчётом из чертежа.
7. **Возвышение.**
   `uv run python skills/railway-design/scripts/cant_calc.py --curves "V:R,..."`
   → h по кривым со статусами и источниками. Подписи h — в ведомости кривых (слой `RW-GRADE`). Нормативы и отображение — [references/cant-and-gauge.md](references/cant-and-gauge.md).
8. **Стрелочные.**
   `uv run python skills/railway-design/scripts/turnout_geometry.py --mark 1/11 [--length .. --a ..] [--crossover E]`
   → угол α, альбомные данные (пока пользователь не ввёл альбомные числа — на чертёж их не ставить). Условные обозначения через `block` — [references/turnouts.md](references/turnouts.md).
9. **Компоновка листа.** Рамка/штамп (`RW-FRAME`, блоки с атрибутами), размеры (`annotation` → `create_dimension_*`), `view` → `zoom_extents`. Печать: `drawing` → `plot_pdf` с `scale_mode: "fixed"`, `scale: "1:2000"` (или заданный); fit-печать — только с `declared_scale: "NTS"`.
10. **Верификация и выдача.** `drawing` → `audit` + `audit_geometry`; разбор findings у источника. `drawing` → `render_preview` после каждого этапа (шаги 4–9) и финально; проверка PDF (масштаб, непустота, читаемость). `drawing` → `deliver` — пакет с SHA-256. Отчёт — по Output Contract.

Сеанс целиком (бэкенды, FIFO, постусловия сервера): [references/mcp-workflow.md](references/mcp-workflow.md). Термины: [references/glossary.md](references/glossary.md).

## Лазы надёжности (Reliability Gates)

| Gate | Условие прохода | При провале |
|---|---|---|
| INTAKE_GATE | Категория/скорости, геометрия ВУ, масштабы заданы; TBD перечислены явно | Только расчётные таблицы и заготовки; черчение оси — BLOCKED |
| SCRIPT_GATE | Все задействованные скрипты прошли `--self-test` в этой среде | Не чертить по непроверенной геометрии; починить среду/скрипт |
| DOCUMENT_IDENTITY_GATE | `drawing.context` совпал с ожидаемым после каждого открытия/сохранения/печати; мутации с doc_id+expected_revision | Стоп, `E_DOCUMENT_ID_MISMATCH`; один recovery, затем смена бэкенда |
| POSTCONDITION_GATE | requested/actual/diff каждой мутации объяснены; стыки оси сходятся в 1e-6 м; слои = схеме | Стоп зависимого черчения; recovery; затем BLOCKED |
| TRANSPORT_GATE | Вызовы строго последовательны; ошибок очереди/лимита нет | Стоп раунда, сохранить доказательства, повторить раунд |
| GEOMETRY_DRC_GATE | `audit_geometry` без критических findings на изменённой области | Чинить источник/перегенерировать; не украшать дефект |
| PLOT_SCALE_GATE | Фиксированный масштаб в `plot_pdf` совпал с фактическим; fit ≠ численный масштаб; PDF просмотрен | Перепечатать; на листе с FIT численный масштаб запрещён |
| NORMATIVE_GATE | Все нормативные числа имеют источник или пометку «уточнить» + запись в расчётной таблице | Убрать число из чертежа/отчёта |

Проверки не заменяют друг друга: `render_preview` не доказывает DRC, DRC не доказывает масштаб печати.

## Output Contract

Финальный ответ содержит:

1. **Файлы**: DXF (чертёж), PDF (печать фиксированным масштабом), DXF-заготовки (сетка профиля) — пути + SHA-256 из `deliver`.
2. **Расчётные таблицы** (JSON): по каждой кривой — элементы и координаты (`track_geometry.py`), пикетаж с домером; клотоиды — точки и параметры; возвышение — h/статусы/источники (`cant_calc.py`); переводы — α и альбомные данные с `verified: false` при неподтверждении.
3. **Журнал проверок**: gates → PASS/FAIL/BLOCKED, postcondition-сводка, DRC-итог, plot-scale-доказательство, превью-артефакты.
4. **Открытые позиции**: все «уточнить»-нормативы, TBD intake, допущения, альбомные данные, ожидающие ввода.

## Детерминированные скрипты

Каждый: argparse, `--help`, JSON на stdout, `--self-test` (простые ассерты), exit-коды 0/1/2 (3 — нет ezdxf для profile_grid). Запуск: `uv run python skills/railway-design/scripts/<name>.py`.

- `track_geometry.py` — элементы круговой с клотоидами, координаты НК/НКК/ККК/КК/СЦ/Ц, пикетаж. Вход: `--angle-deg --radius [--spiral] [--station-vu] [--turn]`. Выход: `elements`, `coordinates`, `chainage`.
- `clothoid_points.py` — дискретизация клотоиды (ряды Френеля, без ezdxf). Вход: `--radius|--parameter --length --points --origin-x --origin-y --direction --side`. Выход: `points` для `create_polyline`, `end_tangent_deg`.
- `cant_calc.py` — возвышение h=12,5·V²/R + лимиты. Вход: `--curves "V:R,..."`. Выход: `curves[]` (h_eq, h_applied, status, a_nep, warnings), `constants.sources`.
- `turnout_geometry.py` — угол крестовины α=arctan(1/M), альбомные данные с пометкой, съезд. Вход: `--mark 1/11 [--length --a --rail] [--crossover E] [--table]`.
- `profile_grid.py` — DXF-заготовка сетки профиля (ezdxf, мм листа). Вход: `--length-m --start-pk --h-scale --v-scale --out [--rows]`. Выход: файл + JSON-манифест (SHA-256, счётчики).

Скрипт — узкий валидатор/калькулятор: PASS не доказывает нормативность решений и не заменяет взгляд проектировщика.

## Ограничения

- Кривые на чертеже: круговые — аналитические ARC, клотоиды — аппроксимация полилиниями (шаг по стреле прогиба; число вершин фиксируется в отчёте).
- MCP-сервер не строит Civil-коридоры, поперечники, объёмы; профиль — 2D по сетке.
- Типовые альбомы переводов, действующие редакции нормативов (СТН Ц-01-95, методики РЖД по возвышению, СПДС) — проверяет человек; все «уточнить»-числа не попадают на чертёж без явного ввода.
- Скрипты считают геометрию введённых параметров; выбор проектных решений (радиусы, уклоны, марки, размещения) — проектировщика.
