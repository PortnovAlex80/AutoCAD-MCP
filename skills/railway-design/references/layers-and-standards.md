# Слои, стили и нормы оформления

Читай этот файл при создании/проверке структуры чертежа ЖД-объекта.

## 1. Схема слоёв

Единственный источник истины — машиночитаемая схема [`assets/layer-scheme.json`](../assets/layer-scheme.json): имя, роль, ACI-цвет, тип линии, вес линии, признак печати.

| Слой | Роль | Цвет ACI | Линия | Вес, мм |
|---|---|---|---|---|
| RW-AXIS-DES | ось проектируемой трассы | 1 | CENTER | 0,25 |
| RW-AXIS-EX | ось существующего пути | 8 | CENTER | 0,13 |
| RW-TRACK-DES | проектируемый путь | 7 | CONTINUOUS | 0,50 |

## 2. Применение через MCP

1. Прочитай схему: `assets/layer-scheme.json` лежит рядом с скиллом; поля `name/color/linetype/lineweight` соответствуют параметрам `layer` → `create` (`data: {name, color?, linetype?, lineweight?}`).
2. Создай слои до любого черчения; затем `layer` → `list` и сравни имена/цвета/типы со схемой — это постусловие этапа. Расхождение = несоответствие постусловию (см. SKILL.md, «Лазы надёжности»), дальше не черти.
3. Перед каждым блоком геометрии задавай текущий слой: `layer` → `set_current` (`data: {name}`) и указывай `layer` явно в вызовах `entity`/`annotation` — не полагайся на «текущий».
4. Типы линий CENTER/DASHED/HIDDEN должны быть загружены в документ. В offline-бэкенде ezdxf создай документ с setup (стандартные типы загружаются); если `layer.create` с линией вернул ошибку — создай слой с CONTINUOUS, зафиксируй ограничение в отчёте и (в live-бэкенде) попробуй донастроить через `system` → `execute_lisp` с явным разрешением пользователя.

## 3. Единицы и масштабы — два режима

| Режим | Модель | Содержимое |
|---|---|---|
| План трассы | **метры** (1 ед. = 1 м), координаты — местная/гос. система | оси, путь, переводы, пикетаж |
| Продольный профиль (сетка+линии) | **миллиметры листа** (1:1) | сетка, чёрный/красный профиль, тексты |

- Никогда не смешивай режимы в одном пространстве модели. Профиль удобно вести отдельным файлом (или отдельным листом/пространством) и собирать комплект через компоновку.
- Высоту текста в модели выбирай из масштаба вывода: при выводе плана 1:2000 текст 2,5 мм на бумаге = 5 м в модели; при выводе 1:5000 = 12,5 м. Табличку соответствий веди в расчётной таблице проекта.
- Печать плана: `drawing` → `plot_pdf` с `scale_mode: "fixed"`, `scale: "1:2000"` (paper:drawing). Режим `fit` допустим только с подписью `declared_scale: "NTS"`/`FIT` — численный масштаб на листе с fit-печатью запрещён.

## 4. Тексты и размеры

- Тексты: `annotation` → `create_text` / `entity` → `create_mtext` (для многострочных — отметки, ведомости), высота и слой — явно.
- Размеры: `annotation` → `create_dimension_linear/aligned` для линейных (расстояния, вставки), `create_dimension_angular` для углов поворота θ, `create_dimension_radius` для радиусов кривых. Размеры держи на `RW-DIM`; ассоциативность проверяй `entity` → `get`.
- Выноски (НК, КК, ВУ, ЦП, скважины): `annotation` → `create_leader`.

## 5. Листы и штамп

- Форматы — по СПДС (ГОСТ Р 21.1101); для длин планов трассы применяются увеличенные форматы/разбивка на листы — **уточнить требования конкретной организации-держателя норм**.
- Рамка и штамп — слой `RW-FRAME`; атрибуты штампа (шифр, масштаб, стадия) заполняй через `block` → `insert_with_attributes` / `update_attribute`, если шаблон штампа предоставлен. Форму штампа из памяти не воспроизводить.

## 6. Запреты

- Не рисуй «чёрные» и «красные» линии одним слоем/цветом.
- Не помещай размеры и тексты в один слой с геометрией.
- Не выводи на печать `RW-CONSTR`.
- Не переименовывай слои схемы под задачу: схема общая для всех ЖД-чертежей проекта; изменения схемы — отдельное решение владельца (PR в `layer-scheme.json`).
